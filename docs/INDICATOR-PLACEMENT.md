# 보조지표 이동과 중첩

기본 웹 데모의 **지표 위치·중첩**에서 기존 지표를 다른 패널로 옮기거나, 가격 차트·다른 지표 위에 겹치거나, 새 패널로 분리할 수 있습니다. 패널 순서는 선택 후 위로/아래로 버튼으로 바꿉니다. MACD처럼 여러 출력선을 가진 지표는 한 그룹으로 이동합니다.

배치 변경은 기존 모델에서 표시 바인딩만 바꿉니다. 지표 계산을 다시 실행하거나 OHLCV 데이터를 교체하지 않으며, 현재 시간 범위와 드로잉 이력도 유지합니다. 다른 패널로 옮길 때는 기본적으로 새 독립 축을 선택합니다. **기본 축**을 명시적으로 선택하면 대상 패널의 기존 값 범위를 공유합니다. RSI와 가격처럼 단위가 다른 값은 독립 축을 사용하는 것이 적합합니다.

## 공개 API

```js
// 가격 패널 위에 RSI를 독립된 0–100 축으로 표시합니다.
chart.api.addAxis({
  id: 'rsi-overlay', panel: 'price', side: 'right',
  range: [0, 100], precision: 0,
});
chart.api.setIndicatorPlacement('rsi', {
  panel: 'price', axisId: 'rsi-overlay',
});

// 모든 MACD 출력선을 이미 존재하는 패널의 기본 축으로 옮깁니다.
chart.api.setIndicatorPlacement('macd', {
  panel: 'oscillators', axisId: null,
});

// 현재 패널 ID를 모두 한 번씩 포함해야 합니다.
chart.api.setPanelOrder(['price', 'oscillators', 'volume']);
```

`setIndicatorPlacement(id, {panel, axisId?})`는 해당 지표를 참조하는 모든 시리즈를 함께 변경하고 `{changed: number}`를 반환합니다. `axisId` 생략 또는 `null`은 대상 패널의 기본 축입니다. 지표와 대상 패널이 존재해야 하며, 명시적 축은 그 패널에 속해야 합니다. 출력선이 없는 지표, 알 수 없는 필드와 잘못된 바인딩은 변경 전에 거부합니다. 기존 지표 엔트리·출력 버퍼·범위 캐시·스타일·표시 offset은 유지하고, 시리즈 바인딩은 새 레코드로 교체할 수 있습니다. 같은 배치는 `changed: 0`이며 다시 그리기를 요청하지 않습니다.

`setPanelOrder(ids)`는 현재 패널 전체의 정확한 순열을 받습니다. 순서가 바뀌면 `true`, 같으면 `false`를 반환합니다. 누락·중복·알 수 없는 ID는 거부하며 패널 객체와 데이터는 유지합니다. `ChartModel`에서도 같은 순서 변경 메서드를 사용할 수 있습니다.

`removePanel(id)`는 사용하지 않는 패널만 제거합니다. 마지막 패널, 시리즈나 독립 축이 남은 패널, 현재 드로잉 또는 Undo/Redo 이력이 참조하는 패널은 제거할 수 없습니다. 활성 드로잉 트랜잭션이나 해당 API 컨트롤러의 진행 중인 입력도 배치 변경을 막습니다.

여러 출력선은 검증 후 한 번에 반영하고 변경 알림도 한 번 보냅니다. 다른 API와 마찬가지로 반영 후 호스트 알림에서 오류가 발생했다면 현재 상태를 확인해야 합니다. 알림 오류가 변경 취소를 뜻하지는 않습니다.

## 축과 드로잉 보존

새 패널·독립 축은 원래 지표의 스케일, 범위와 정밀도를 바탕으로 구성합니다. 서로 다른 원본 패널·축에 걸친 출력선을 합칠 때는 선형 자동 범위를 사용하며 화면에 이를 알립니다. 독립 퍼센트 축에는 유한한 0 아닌 기준값이 필요합니다.

이미 그린 도형의 좌표와 바인딩은 자동 이동하지 않습니다. 시리즈에 연결된 도형은 그 시리즈가 다른 패널·축으로 이동하면 기존 계약에 따라 숨겨진 orphan 상태가 되고, 같은 바인딩을 복원하면 다시 나타납니다. 관련 패널·축과 드로잉 이력은 보존합니다. 자세한 의미는 [독립 축 계약](INDEPENDENT-AXES.md)을 참고하세요.

데모는 자신이 생성한 빈 패널·축만 정리합니다. 다른 지표가 공유하거나 도형 이력이 참조하는 패널·축은 유지합니다. 추가 지표 전체 삭제 역시 기존 지표가 사용 중인 공유 패널을 제거하지 않습니다.

## 저장과 실행 범위

기존 [workspace](WORKSPACES.md)는 패널 순서, 축과 시리즈 바인딩을 이미 저장하므로 스키마 변경이 없습니다. `saveStudies()`도 지표 시리즈의 배치를 보존하지만, `loadStudies()`를 호출할 호스트가 필요한 패널·축을 먼저 준비해야 합니다. 같은 데이터셋에서 데모 데이터 수를 바꾸거나 렌더러를 교체해도 배치를 이어서 사용합니다.

세 명령은 JavaScript API와 공통 native JSON command facade에서 사용할 수 있습니다. 웹 화면 조작은 기본 데모에 구현되며, 네이티브 화면의 이동 컨트롤을 추가한 것은 아닙니다.

`npm run test:indicator-layout:browser`는 실제 Chrome에서 이동·중첩·분리·패널 순서, 지표 버퍼와 차트 상태 보존, 공유 패널 정리, 입력 중 거부와 반응형 화면을 검사합니다. GitHub CI에서도 이 검사를 실행합니다. 터치 실기기와 스크린 리더 검증은 별도입니다.
