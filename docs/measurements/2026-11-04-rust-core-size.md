## Android 배포 크기

출하 프로필은 `opt-level=s`, `panic=unwind`, fat LTO다. SDK 합계는 ABI별 `.so + classes.jar + JS 코어 자산(포함 시)` AAR 엔트리 바이트다. APK 압축·R8·설치 크기는 별도다.

| ABI | JS 전용 SDK | Rust 전용 SDK | 두 백엔드 SDK | 두 백엔드 .so |
| --- | ---: | ---: | ---: | ---: |
| arm64-v8a | 1,722,945 | 2,888,701 | 4,425,570 | 3,637,056 |
| x86_64 | 1,780,505 | 3,468,253 | 5,065,898 | 4,277,384 |

최초3 MiB 예산은 전체 코어 실측에서 초과했다. 2026-11-04 소유자는 듀얼 유지와 **5,242,880 B(5 MiB)/ABI**를 승인했다. 위 당시 표의 여유는 arm64 817,310 B, x86_64 176,982 B다. 2026-11-15 갱신한 현재 듀얼 SDK의 여유는 **arm64 780,264 B, x86_64 135,064 B**다. 시작500ms·팬16.7ms 기준은 변경하지 않았다.

JNI와 공통 C ABI만 공개하고 Android 재배치 압축과 safe ICF를 적용했다. 모든 측정 `.so`의 PT_LOAD 16 KiB 정렬을 확인했다. `panic=abort`는 비교용이며 출하 후보가 아니다.

## 남은 검증

[설계 §5.5](../superpowers/specs/2026-11-02-rust-core-design.md#55-산출물과-크기)의 산출물·예산 결정은 반영됐다. 예산 상향은 임계값만 바꾼 결정이며, 위 역사 표의 바이너리는 당시 검토 수정을 포함한 소스로 빌드했다. 후속 패키징 갱신은 상단 주석과 기계 보고서의 출처를 따른다. 크기 예산 충족과 개발 기본값 전환은 실기기 성능·soak·접근성 릴리스 검증의 통과를 뜻하지 않는다.

이전 부분 이식 수치와 LOC 외삽을 전체 코어의 상한이나 배포 결정 근거로 사용하지 않는다.
