# Security, performance, lifecycle and UI review (2026-10-21)

This source review starts from development commit
`7347f0f03b1b9867698dfa2d8cbeadfe818db1b7`. It is not a stable SDK release,
security certification or browser/native performance claim.

## Corrected findings

- **P2, defensive input invariants:** external series validation checked one
  iterator pass but copied another. The conversion now validates each raw value
  actually copied, before coercion. Existing two-pass iteration, full-tail
  validation, typed NaN/null gaps and the typed-column prefix optimization remain.
- **P2, data atomicity:** a bar-field getter could replace or mutate a store
  during `update(index, bar)`, allowing the old index to publish a ghost row.
  Update now rejects a changed source snapshot before its own writes; committed
  inner changes and their notifications survive.
- **P2, render lifecycle:** formatter/renderer callbacks could destroy, replace,
  invalidate or nest a draw while the older draw subsequently painted or
  published stale caches, metrics and errors. Draw generations, owner checks,
  invalidation checks and staged scene caches now retire obsolete work. GPU
  fallback schedules a fresh owned frame instead of synchronously continuing
  obsolete work on the replacement canvas. Direct stale exceptions still reach
  their caller, without poisoning a newer render; current errors still report.
- **P2, React recovery:** changing invalid initial interaction props to valid
  props now retries failed initialization once per changed descriptor signature.
  Live charts synchronize settings without remounting. Cleanup owns the latest
  successful attempt, including factory-created models.
- **P2, control work on hover:** optional drawing panels and toolbars skip only
  dispatch-scoped, library-originated hover notifications. Every public state
  event is still delivered. Non-hover, manually created and replayed events
  refresh normally; action-time checks and off-page validation remain intact.
- **P2, demo readiness and accepted values:** first-load cancellation/failure
  keeps chart-dependent controls disabled and direct handlers safe, with honest
  retry text. Analysis imports synchronize VWAP controls, display custom or
  missing configurations honestly, and preserve imported values. Pending Worker
  correction disables blocked controls and restores accepted values on exit.
- **P3, UI state:** main-demo exploration pressed state follows replacement
  models/renderers rather than displaying the retired explorer's state.
- **P3, finite geometry:** panel weights are normalized before proportional
  arithmetic, avoiding overflow for supported large finite weights without
  imposing arbitrary new caps.

The accessor cases require executable host objects; ordinary JSON cannot encode
those getters. They demonstrate invariant/atomicity failures, not a new remote
code-execution privilege boundary. No confirmed DOM-injection or remote-execution
vulnerability was established in the reviewed scope.

## Measured performance scope

Matched ABBA runs used Node 24.19.0 on one cloud machine, the same harness and
fixtures, 50 warmups and 11 batches. At 10,000 drawings with both optional controls,
median synchronous hover work was **8.719 / 9.276 ms before** and
**0.001387 / 0.001433 ms after** in the two runs for each revision. Across 100
hover events, drawing-ID reads fell from **2,000,000 to 0**, full-array scans from
**200 to 0**, toolbar assignments from **2,400 to 0**, and status appends from
**100 to 0**. All 100 public events remained observable; one RAF was queued and
no renderer was called during the measured event batch.

These are CPU-only modeled-DOM observations, not browser FPS, end-to-end latency,
layout/paint, GPU, mobile or native measurements. Direct host drawing mutations
must request an explicit refresh or non-hover invalidation; hover is not a
mutation notification. Normal drawing refresh remains O(n).

## No-change findings and limits

- Explicit trusted indicator source registration remains outside JSON dispatch.
  Reviewed DOM outputs use textContent, not HTML insertion. Existing prototype
  key, bounded/duplicate/deep JSON and drawing-anchor checks remain in place.
- Warmed fixed-viewport layout reused its indices across 1k, 100k and 1m source
  bars in the focused samples; no scaling rewrite was justified. Drawing history
  retained immutable sharing and its existing budget.
- Some successful data facade calls still emit two state events. Deduplicating
  those could change standalone/custom invalidator and direct-store semantics;
  no unproven event architecture rewrite was made.
- Existing shared-model, async cancellation, linked cursor/range and history
  regressions passed the focused reviews; no additional change was justified.
- Verification uses ordinary Node execution, modeled DOM/hooks/renderer failure,
  generated JavaScript in Node's V8 VM, syntax/types and offline packaging.
  Actual React/StrictMode, browsers, pixels, touch, screen readers, physical GPU
  fallback, Mac/native SDK/JNI and QuickJS execution were not performed.
- No new shortcut remapping, docking, settings persistence, native UI parity,
  publication or license changes are part of this review.

The maintained regression suites include `api-values-publication`,
`bar-update-snapshot`, `panel-weight-proportions`, `canvas-render-reentry`,
`gpu-fallback-lifecycle`, `react-initialization-retry`, `state-notification`,
`demo-readiness` and `analysis-demo-controls`. Together they add 116 tests;
independent baseline runs reproduced the underlying failures before acceptance.
