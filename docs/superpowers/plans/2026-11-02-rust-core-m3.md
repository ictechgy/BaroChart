# Rust 코어 M3 구현 계획: 지표 · 체크포인트 · 증분 계산

## 목표와 선행 조건

35 builtin과 정적 linked `aster.volume-direction@1/pressure`를 현재 JS 번들과 같은 상태·출력·문서·오류로 옮긴다. 임의 JS factory/source는 기존 주인 결정대로 제외한다. 이 계획은 구현 순서이며 아직 실행 결과가 아니다.

선행 통합은 [M2 계획](2026-11-02-rust-core-m2.md)의 contracts/codec, Bar/Columns/BarStore/DataChange, markets/portable calendar, ingestion이다. 모델/장면/전체 workspace는 M4가 담당한다. M2 draft leaf 통과 수치만으로 bridge parity를 주장하지 않는다.

정본: [설계](../specs/2026-11-02-rust-core-design.md), [Tier-A 지도](../specs/2026-11-02-rust-core-porting-map-tier-a.md), 현재 `src/core/indicators.mjs`, `checkpoint-validation.mjs`, `indicator-params.mjs`, `indicator-modules.mjs`, `trusted-studies.mjs`, `session-studies.mjs`, `study-setup.mjs`, `native-checkpoints.mjs`.

각 source에 대응하는 Rust 테스트 파일을 같은 소유자가 맡는다. Native Swift/Java/FFI/CI는 root만 통합한다. Rust는 unsafe 금지(FFI만 예외), 런타임 의존성 추가 금지, 한국어 공개 Rust 문서를 유지한다.

## 공통 인터페이스

- `IndicatorProgram`: 35 builtin과 Pressure의 고정 enum. Registry는 고정 순서 name→kind/metadata이며 임의 callback registry를 만들지 않는다.
- `IndicatorDefinition`: program, 원래 의미를 보존한 ordered raw params, 출력 이름 순서, plot offsets, builtin/linked provenance. Unknown params도 저장 문서에서 보존한다.
- Plot offset은 **f64**로 보존한다. i32로 바꾸면 Ichimoku `chikou=-displacement`의 displacement 0에서 생기는 `-0`, pressure shift `-0`를 잃는다. 인덱스에 쓸 때만 검증된 정수를 변환한다.
- 계산 leaf는 `create(kind, params)`에서 definition과 자신의 typed state를 만들고 `step(state, &Bar, index, outputRow)`를 제공한다. Hot loop에 JsValue 상태나 매행 heap output 배열을 쓰지 않는다. 공통 기반은 아직 없는 leaf state 타입을 참조하지 않는다.
- Root가 leaf 완료 뒤 그룹별 state enum을 감싼 전체 `IndicatorState`와 dispatch를 만든다. 이로써 순환 의존이나 공통 enum 동시 수정을 피한다.
- 세션 지표의 factory와 step은 `&dyn Host`를 명시적으로 받는다. Calendar timezone 검증은 factory에서 이미 일어나므로 step까지 미루지 않는다. Portable calendar의 `earlier`/`later`/`reject`를 유지하기 위해 leaf adapter가 기존 markets 날짜·시간 함수에 같은 ambiguity를 전달한다.
- Checkpoint wire 변환은 경계에서만 실행한다. 상태 비교는 f64의 `Object.is` 의미(±0 구분, NaN 동치)를 쓰며 derive PartialEq로 대체하지 않는다. 초기 `{}`와 아직 생성되지 않은 helper 필드는 Option/presence로 구분하고, 첫 step에서 생기는 키의 삽입 순서를 보존한다. imported state의 허용된 키 순서는 wire snapshot에서 유지하되 equalState는 키 순서를 비교하지 않는다. Extreme queue canonical snapshot은 source처럼 새 `{a,head:0}` 순서로 만들며 live state를 임의로 canonicalize하지 않는다.
- Engine은 BarStore를 보유하거나 borrow를 host 호출 사이에 저장하지 않는다. 각 계산 호출이 `&BarStore`를 받고 DataChange를 명시적으로 전달받는다.
- Store commit → ingestion ledger의 실패 불가 갱신 → indicator/model 내부 invalidation → 외부 listener 순서를 유지한다.

Registry의 builtin 부분은 source의 35개 순서로 fixture화한다. 정상 번들은 trusted-studies를 시작 시 링크하므로 새 IndicatorEngine의 registry에는 pressure까지 36개가 이미 있다. 순수 metadata Registry의 35개 초기값과 구분하고, 런타임 엔진 생성 시 정적 pressure를 등록한다. 공개 registerIndicatorModule 호출 전에도 pressure add가 성공해야 한다. Ichimoku offsets는 spanA:+d, spanB:+d, chikou:-d이며 pressure는 두 출력에 shift다.

## 검증·상태 계약

1. 공통 params 검증(최대 32개, 값은 유한 number 또는 string, calendar string 상한 별도)과 각 factory의 default/null/undefined/unknown-field 의미를 구분한다. Factory별 검증 순서를 추측하거나 일괄 정규화하지 않는다.
2. Ring, smoother, monotonic deque, compensated VWMA의 식과 괄호·평가 순서·snapshot 물리 배열 순서를 그대로 옮긴다. Mature smoother sum의 +0 canonicalization, 극값 queue의 만료 항목 제거와 head=0를 보존한다.
3. Source에 필요한 수학은 sqrt/floor/abs와 JS kernel min/max/sign이다. 현재 지표 경로에 pow/sin/cos/log/exp/hypot은 없다. 측정하지 않은 libm 동등성 가정을 추가하지 않고 M3 때문에 WASM import를 임의로 늘리지 않는다. sqrt는 tolerance 없이 정확히 비교한다.
4. Live checkpoint는 ordinary BTreeMap이다. Native restore/params staging의 bounded container는 별도 타입으로, record 262144 bytes/총 ledger 33554432 bytes와 retirement를 지킨다. Publish 뒤 ordinary map으로 소유권을 옮기고 ledger를 live engine에 남기지 않는다.
5. Checkpoint 크기 256, dirty/dirtyTo/invalidated/length/revision/computedFrom/computedUntil/preparedVersion/generation/running의 초기값과 전이를 source대로 옮긴다. 새 계산은 중단된 token을 supersede하고 running은 실제 step 재진입만 거절한다.
6. Store 변경은 즉시 계산하지 않는다. apply의 lazy throw를 데이터 변경 시점으로 당기지 않는다. 반면 현재 IndicatorEngine.add는 entry를 넣은 뒤 get으로 즉시 계산하며 실패 시 그 entry를 제거하므로 add를 임의로 lazy로 바꾸지 않는다. 계산 실패 시 부분 output/checkpoint write와 clean metadata 미게시를 그대로 유지한다(일괄 rollback으로 바꾸지 않는다).
7. Canonical builtin만 convergence를 사용한다. Pressure는 causal descriptor가 true여도 canonical builtin이 아니므로 convergence를 사용하지 않는다.
8. Save/loadStudies와 params 교체는 schema/output/offset/module descriptor 검증 뒤 staging하고 원자 swap한다. Advanced vwap/pivots는 명시적 기본 옵션만으로도 상태 스키마가 달라질 수 있다.

## 필수 실행 증거

각 checked-in vector는 oracle commit, bundle SHA256, schema/seed/dialect/platform/ICU/tzdata, kind/params/output order/offset, call sequence와 store version을 기록한다. Private scratch corpus에 의존하지 않는다. Pure leaf는 실제 JS helper에, bridge는 실제 번들에 대조한다.

- 35+pressure cold fold: ordinary/flat/zero-volume/negative/±0/subnormal/1e300/MAX_VALUE와 exact state JSON.
- Incremental: 10000 append, current replace, 깊은 correction, prepend/reset/batch를 매 단계 fresh engine과 Object.is 비교한다.
- Checkpoint: 0/255/256/257/512, convergence boundary, 손상/누락 history, record/total 예산 및 publish 후 ledger 제거.
- 실패: output arity/type/Infinity, extreme throw table, 부분 arrays/checkpoints, 같은 위치 retry, capacity/output budget 원자성.
- 수명: suspended supersession, same-entry reentry, nesting 32/33, store/columns replacement, remove/dispose.
- 조회·문서: raw/plot/asOfIndex, named outputs, params의 -0, exact descriptors, duplicate/stale/module-version rejection, schema/offset 변경 거절.
- 플랫폼: WASM/V8, Apple/JSC, Android/QuickJS를 같은 플랫폼 기준으로 비교한다. 세션은 DST gap/fold와 Santiago 경계를 포함한다.

기존 tolerance 기반 지표 테스트만으로 M3를 닫지 않는다. 독립 analytic 계산기는 보조 근거이며 최종 기준은 같은 플랫폼 JS다.

## Native 연결과 완료 기준

Root는 add/remove/set params, values/valueAt, module registration, save/loadStudies, nativeIndicatorBuffer를 단일 manifest와 Engine에 연결한다. 현재 Android Rust indicatorSlice가 id/output/offset/count를 버리는 stub 배선은 **M3에서 handler를 켜기 전에** 고친다. Swift Rust runtime에는 C ABI f64 직접 read/write가 필요하다(M1c로 확인). Async params job 자체는 M6이지만 DTO와 staging 계약은 M3가 제공한다.

완료는 전체 cold/incremental/checkpoint/query/document corpus, Rust fmt/check/clippy/bans, Node/타입/패키지, unskippable WASM 대조와 양 플랫폼 native gates가 모두 통과한 뒤에만 기록한다. 장면·상호작용·실기기 chart performance와 public backend rollout은 M4~M7이다.
