# Rust 코어 M2 구현 계획: 계약 · 데이터 · 시장/시간 · 수집 · 드로잉

## 목표와 현재 상태

**목표:** 기존 JavaScript 코어의 데이터와 문서 표면을 Rust로 옮겨 M2 범위의 브리지 호출을 JS 백엔드와 바이트·비트 단위로 맞춘다. 이 계획은 구현 순서와 합격 기준을 정한다. 측정하지 않은 결과를 통과한 것으로 적지 않는다.

`rust/crates/barochart-core/src/lib.rs`에는 M1b에서 만든 `Engine`, `Host`, `HostError`가 이미 있다. `barochart-bridge`에는 현재 `nativeInit` 왕복 골격이, `barochart-ffi`에는 C ABI가, `barochart-wasm`과 `scripts/rust/wasm-harness.mjs`에는 V8 대조 하네스가 있다. M2는 이 기반을 **확장**한다. 새 엔진, 호스트 오류 타입, 별도 dispatch 표, FFI 또는 WASM 런타임을 다시 만들지 않는다.

iOS에는 공개 JSValue-returning API 호환을 위한 **value-only `RustValueRealm`** (`native/BaroChartRustCoreRuntime.swift`)이 이미 들어 있다. 코어 번들이나 사용자 코드를 평가하지 않는 JSC 값 재료화 shim이다. 이것을 Rust fallback으로 취급하지 말고 유지한다. Rust F64 buffer copy-in/copy-out, recording/trace transport 및 packet 연결은 M2 이후 M6의 별도 연결 작업이며 이 M2 데이터 구현만으로 완료됐다고 표시하지 않는다.

정본은 다음 문서다.

- [Rust 코어 설계](../specs/2026-11-02-rust-core-design.md) §6, §7, §8.1, 특히 오류·수학·플랫폼 계약
- [이식 지도](../specs/2026-11-02-rust-core-porting-map.md) §3.2~§3.6, §3.10, §4.2~§4.4, §4.8, §5와 부록 B
- [Tier-A 이식 지도](../specs/2026-11-02-rust-core-porting-map-tier-a.md) §2, §3.0, §3.3, §3.5~§3.10
- M1의 [Rust 코어 계획](2026-11-02-rust-core-m1.md) 공통 빌드·의존성·금지 규칙

## M2 구성과 의존성

M2는 세 변경 묶음으로 나눈다. **Task 0은 통합 소유자 한 명이 맡는다.** Task 0 뒤 leaf lane은 아래 의존성대로 분리한다.

| 변경 묶음 | 작업 | 선행 조건 | 소유 경계 |
|---|---|---|---|
| M2a `feat/rust-m2a-data-store` | Task 0 A0, Task 1 contracts/코덱, Task 2 데이터 | 순서대로 | Task 0 통합 소유자가 `barochart-core` 엔진/호스트·`barochart-bridge` dispatch·Cargo·드라이버를 소유한다. contracts/코덱 뒤에 data lane을 연결한다. |
| M2b `feat/rust-m2b-markets-ingestion` | Task 3 markets, Task 4 full Tier-A ingestion | Task 0. markets는 독립 lane. ingestion은 Task 1과 Task 2 완료 뒤 통합한다. | markets는 `markets.rs`와 자체 검증. ingestion은 `ingestion.rs`, 오류, 데이터 통합 경계만 소유한다. dispatch/Engine 공통 변경은 Task 0 소유자가 통합한다. |
| M2c `feat/rust-m2c-drawings` | Task 5 드로잉 저장소·검증·문서·그룹 편집 | Task 0과 Task 1 | drawings 모듈과 해당 leaf 테스트를 소유한다. dispatch/Engine 공통 변경은 Task 0 소유자가 통합한다. |

Task 0 소유자는 `rust/crates/barochart-core/src/lib.rs`와 `engine.rs`/`host.rs`가 필요한 경우의 기존 정의, `Cargo.toml`/`Cargo.lock`, `barochart-bridge` 함수 표와 dispatch, `scripts/rust` 공통 대조 driver를 단독 통합한다. Leaf 작업자는 이 파일들을 중복 정의하지 않고 자신의 모듈·전용 테스트에 집중한다. FFI·WASM 포인터 처리는 계속 `barochart-ffi`에만 두며 새 unsafe 블록을 코어에 추가하지 않는다.

## 공통 구현 규칙

- **오라클:** M0a 이후의 `src/core`와 현재 `native/Resources/aster-core.js`. Node 비교는 이 저장소 번들을 `node:vm`에서 실행한다. `src/core` 직접 호출은 pure leaf 함수 검증에만 쓴다. 브리지 시나리오는 항상 번들에 있는 실제 `native*`/`nativeCommand` 호출로 대조한다.
- **같은 시나리오, 같은 수명:** 한 시나리오의 JS VM과 Rust `Engine`은 각각 한 번 만들고 호출 전체에서 재사용한 뒤 해제한다. 엔진마다 serial, ingestion epoch, drawing serial을 보존한다. 서로 다른 엔진 간 비교에서만 명세상 process-global identity를 정규화한다.
- **재현 가능한 증거:** `/private/tmp`나 외부 probe 파일에 의존하지 않는다. 기준 벡터는 현재 체크인된 Node 테스트에서 뽑아 `test/fixtures/rust-core-vectors/`에 둔다. 각 fixture에는 oracle git commit, `aster-core.js` SHA-256, schema version, seed, `NumberDialect`, 실행 플랫폼 및 `tzdata`/ICU 버전을 기록한다. 이 메타데이터가 없는 기대값은 승인된 golden이 아니다.
- **비교 규칙:** JSON과 문서는 무손실 writer로 생성된 UTF-8 텍스트를 바이트 비교한다. 오류는 `name`, `message`, `code`를 각각 비교한다. F64는 `Object.is` 의미(−0 구별, NaN 동치)와 사용처에서 관찰 가능한 raw bit pattern을 비교한다. 원자적 실패 테스트는 실패 전후 ledger/state도 비교한다.
- **수치 방언:** `barochart-js::num::NumberDialect`를 경계까지 명시적으로 전달한다. Node/V8와 Apple/JSC에는 ECMAScript 방언, Android/QuickJS에는 `QuickJs` 방언을 쓴다. `NumberDialect::PLATFORM`의 기존 기본값은 바꾸지 않는다. 체크포인트·JSON parse/stringify 역시 같은 선택을 받게 한다.
- **시간대:** `barochart-js::date`의 TimeClip, ISO, civil-date 코드를 재사용한다. chrono류 의존성을 넣지 않는다. 유한성·문법·연도 범위를 확인하고 TimeClip 한 뒤에만 `Host` offset 콜백을 부른다. 플랫폼 tzdata 차이는 버전 메타데이터와 전이 벡터로 확인한다.
- **검증 우선:** 옵션, 형태, 깊이/길이, 예산, 순서, 넘침 검사의 JS 순서를 유지한다. 검증이 끝나기 전에 외부 상태를 바꾸지 않는다. 커밋 경계 뒤에는 실패 가능한 작업을 두지 않는다.
- **TDD:** 각 task는 해당 leaf/bridge 회귀 테스트를 먼저 추가하고 실패를 재현한 뒤 구현한다. fixture, Rust test, 플랫폼 gate가 실제로 실행되기 전에는 체크 표시나 pass 결과를 기록하지 않는다.
- **회귀 경로:** Rust 변경마다 해당 `cargo test`와 실제 WASM 번들 대조를 먼저 통과시킨다. 완료 단계에서 `npm test` 전체, `cargo check --locked --offline --workspace --all-targets`, `cargo test --locked --offline --workspace`, `cargo fmt --all -- --check`, `REQUIRE_WASM=1` WASM 테스트를 실행한다. Cargo는 항상 `node scripts/rust/cargo.mjs ...`로, `--offline --locked -j2`를 사용한다.

## Task 0 — A0 manifest, 기존 엔진 통합, 실제 conformance driver

**소유자:** M2 통합 소유자. 이 작업이 끝나기 전 leaf 작업은 bridge dispatch나 `Engine` 공통 코드를 바꾸지 않는다.

**수정/추가 파일:**

- Extend: `rust/crates/barochart-core/src/lib.rs`의 기존 `Engine`, `Host`, `HostError`; 필요하면 기존 타입을 유지한 채 `engine.rs`/`host.rs`로 모듈 분리
- Extend: `rust/crates/barochart-bridge/src/lib.rs`의 단일 함수 manifest와 `call`/`supports`
- Extend: `rust/crates/barochart-core/Cargo.toml`, `rust/crates/barochart-bridge/Cargo.toml`, `rust/Cargo.lock`
- Extend: `scripts/rust/wasm-harness.mjs`; create: `scripts/rust/core-conformance.mjs`; test: `test/rust-core-conformance.test.mjs`
- Create: `test/fixtures/rust-core-vectors/manifest.json`와 lane별 JSONL/기대 바이트

### A0 manifest 계약

1. 현재 JS 번들의 초기 100개 bridge global을 실제 소스에서 세어 `manifest.json`에 고정한다. 각 이름은 `implemented`, `reject`, `pending` 중 하나로 기록하고 출처 파일/행과 Rust 핸들러를 연결한다. 개수는 100이어야 한다.
2. `implemented`는 실제 handler로 간다. `reject`는 의도적으로 JS 전용인 Tier-A 정책을 따라 정확한 `UnavailableError` name/message/code로 끝낸다. `pending`도 **정의된 함수**이며 단계적 unavailable 오류를 낸다. 정의된 pending/reject 이름은 `supports(name) == true`; 100개 표 밖 이름은 false다. A0에서 `nativeCommand`의 operation 표도 map §3.5 arity와 연결해 출처를 남긴다.
3. `nativeRegisterIndicatorSource`, linkable custom module rejection, 데모/셀프테스트/테스트 수명 이름은 Tier-A §2.5~§2.6의 정확한 분류를 따른다. `nativeSelfTest` 같은 정의된 stub과 임의의 unknown 이름을 같은 표 항목으로 취급하지 않는다.
4. 단일 dispatch 표가 `supports`와 `call`의 유일한 근거다. 이미 있는 `Engine: Send + !Sync`, `Host: Send`, `HostError`를 유지하고 host callback을 새 단위 오류로 바꾸지 않는다. 데이터 모델 상태는 Engine이 소유하며 static/thread-local로 엔진 상태를 보관하지 않는다.

### 실제 bridge 비교 경계

기존 `wasm-harness`의 C ABI 호출과 Node `Intl` imports를 재사용한다. `core-conformance.mjs`는 한 시나리오 fixture마다 JS `node:vm` context와 WASM Engine 하나를 만들고, 같은 call 목록을 순서대로 보낸다. JS 쪽은 `native/Resources/aster-core.js`의 `nativeInit`, `nativeCommand`, `nativeDataIngestionCommand` 등 실제 이름을 부른다. Rust 쪽은 같은 이름과 BCJSON arguments를 `barochart-bridge`로 보낸다. 호출 결과뿐 아니라 지정된 지점의 `nativeInspect`, save 문서, ledger, 실패 전후 상태도 fixture에 포함한다. 성공 여부나 요약 count만 비교하지 않는다.

Pure leaf 테스트와 bridge 대조는 분리한다. leaf Rust unit tests는 Rust 모듈의 내부 분기/경계에 집중하고, Node direct-import tests는 해당 JS helper 확인에만 쓴다. bridge parity는 번들에서만 호출해 public global/table mapping을 검증한다.

**A0 acceptance:** `manifest.json`에 정확히 100개, 모든 known names가 분류됐고 `supports`가 known/unported/unknown을 구분한다. 초기 A0 smoke는 M1 scaffold의 현재 `nativeInit(0,null)` 왕복만 확인하며, count/초기 store parity를 뜻하지 않는다. `nativeInit`의 데이터 상태 초기화와 JS 호환 반환은 Task 2에서 구현·fixture화한다. staged unavailable, unknown 이름, 엔진 닫힘/poison/busy의 기존 FFI 오류가 유지된다. `core-conformance.mjs --list`가 manifest와 fixture 목록을 출력하며, 모든 비교 결과에 manifest hash와 oracle metadata가 남는다. M1에서 이미 구현된 functions/errors/host callback/FFI/WASM은 이 시점에서 새로 구현하거나 mock하지 않는다.

## Task 1 — contracts와 체크포인트 codec

**선행:** Task 0. **병렬 가능:** Task 3 markets와 데이터 작업 준비.

**파일:** create `rust/crates/barochart-core/src/contracts.rs`, `src/checkpoint_codec.rs`; tests `rust/crates/barochart-core/tests/contracts.rs`, `tests/checkpoint_codec.rs`; vectors `test/fixtures/rust-core-vectors/contracts.jsonl`, `checkpoint-codec.jsonl`.

**Contracts API:** map §3.2에 맞춰 `RESOURCE_LIMITS`, `option_record`, `canonical_keys`, `ordered_record`, `bounded_text`, `size_limit`, `identifier`, `portable_color`, `portable_font`, `portable_style`를 구현한다. `canonicalKeys`의 M0a 순서(allowed order, UTF-16 정렬한 기타 문자열, 마지막 원래 순서의 symbol)를 그대로 둔다. 반환 문서에는 `PANEL_KEYS`, `AXIS_KEYS`, `SERIES_KEYS`, `THEME_KEYS`, `SYMBOL_KEYS`와 drawing key lists를 같은 순서로 쓴다. `portableStyle`의 null/fill 및 `preserveHex` 동작을 키마다 테스트한다.

**Checkpoint API:** `safe_checkpoint_stringify`, `safe_checkpoint_parse`는 UTF-16 string/key 보존을 위한 `barochart_js::json` entrypoint와 명시적인 `NumberDialect`를 사용한다. Stringify 사전검사는 cycle/prototype/accessor/array-shape/depth·node/Unicode 순서 뒤에 JS JSON writer를 사용한다. Parse는 아래 순서를 유지한다.

1. 입력 타입/UTF-16 8,388,608 길이 검사
2. 문자열 이스케이프를 무시하는 raw scan에서 중복 object key, 깊이 32, 비유한 숫자 token 검사
3. dialect로 JSON parse
4. iterative depth/node/Unicode/number-marker decode 검사

`$asterNumber` marker는 object에 이 key 하나만 있고 값이 `NaN`, `Infinity`, `-Infinity`, `-0`일 때만 복원한다. 중복 키, `1e400`, `-`, `1.2.3`, raw `-0`, `1e-400`, 32/33 깊이, 250,000/250,001 node, lone surrogate를 단계별로 고정한다. 각각의 first-failure error 이름/문구/코드도 fixture로 남긴다.

**Acceptance:** `cargo test --locked --offline -p barochart-core --test contracts --test checkpoint_codec`; `node scripts/rust/core-conformance.mjs --suite core-contracts,core-checkpoint-codec`. Checkpoint writer의 모든 출력 바이트가 oracle fixture와 같고 parse→write는 정의된 비정규 입력의 golden과 같아야 한다. `cargo fmt` 통과.

## Task 2 — data store, RangeIndex, batch transaction

**선행:** Task 0, Task 1. **소유 lane:** `data.rs`, `block_index.rs`, `data_batch_options.rs`, 데이터 tests/vectors. Engine field/dispatch integration은 Task 0 소유자가 한다.

**파일:** create `rust/crates/barochart-core/src/data.rs`, `src/block_index.rs`, `src/data_batch_options.rs`, tests `tests/data.rs`, `tests/range_index.rs`; vectors `test/fixtures/rust-core-vectors/data.jsonl`.

`ModelDataState`는 `BarStore`를 소유한다. Task 4에서 같은 owner에 ingestion session을 붙일 때 Store와 Session을 disjoint borrow로 얻을 API를 이번 task에서 정한다. `BarStore`는 6개의 Float64 columns, `length`, power-of-two `capacity`, `maxBars`, `timeframeMs`, `timeOrigin`, `version`, `timeVersion`, serial/geometry identity, volume `RangeIndex`를 가진다. `bytes = 96*capacity`; capacity 정책은 초기/set/prepend는 16에서 시작해 double, append는 부족 시 double, batch는 기존 capacity에서 double이다. 외부 상태 serial은 global이 아니라 엔진마다 둔다.

**필수 동작:**

- `validate_bar`, `set_data`, `set_columns`, `append`, `update`, `at`, `lower_bound`, `prepend`, `seeded_columns`, 6종 `DataEvent`, `apply_events`를 map §3.4.1~§3.4.9/§3.4.11 순으로 추가한다.
- `RangeIndex`의 left+right tree merge와 dyadic query order를 고정한다. `Math.min/max`의 ±0 규칙, `-0` volume/price, sum overflow 전 상태, finite count, empty range 결과를 bitwise 테스트한다.
- `BlockRangeIndex`는 source values 전체를 복사하지 않고 소스 배열을 빌린 slice로 참조한다. 65,536 경계에서 blockSize 32, ceil lengths, first/last partial scan 및 finiteCount를 검사한다.
- Time 값은 finite, safe integer, `abs <= 8.64e15`, strictly increasing이어야 한다. High/low/volume 검사의 우선순위와 `-0` 보존을 정한다. JS처럼 `-0`과 `+0` time은 동일한 인덱스 시각으로 취급해 증가 검사를 실패시킨다.
- `setColumns`는 허용된 JS typed numeric arrays의 요소를 소유 복사한다. `Float32Array`, signed/unsigned int, `Uint8ClampedArray`, `Float16Array` 등의 변환/검사와 missing column ordering을 fixture로 고정한다.
- batch transaction은 snapshot/validate/stage 후 한 번만 commit한다. 실패 시 columns, indexes, versions, listeners, ingestion state 모두 그대로여야 한다. 검사 순서는 **batch options → event array/shape → store/queue budget → chronology → overflow/index preflight**이며 각 둘 이상 동시 위반 벡터가 first error를 확정한다.
- batch commit은 version을 한 번 올리고 `timeVersion`은 시간 변경 시에만 올린다. `reset`, `append`, `update`, `correction`, `prepend`, `batch`의 반환 영수증 key 순서를 고정한다. `indexAt`/`timeAt`/`lowerBound`/`at`의 range errors와 operation order를 검증한다.
- 이 단계에서 M1의 count-only `nativeInit` prototype을 교체한다. `nativeInit`은 `ModelDataState`/`BarStore`를 만들어 초기 seed/count data를 소유하고 JS 코어가 반환하는 `0`을 돌려준다. 기본 count, 옵션 형태와 오류 우선순위는 JS bundle fixture에 대조한다. M2는 데이터 상태만 소유하므로 panels/theme/indicators/layout 결과를 이미 완전 이식한 것으로 표시하지 않는다. 이 표면의 남은 manifest 항목은 M3/M4에서 닫는다.

**Checked-in vector source:** `test/data-batch.test.mjs`, `test/data-batch-unchanged.test.mjs`, `test/append-atomicity.test.mjs`의 named cases를 fixture로 옮긴다. Seed 21과 42의 seeded columns, point operations, 1000개 이상 dyadic range queries, random corrections/prepends를 JSONL로 만든다. fixture header에 metadata를 기록하고 7,887 sum comparisons의 기존 baseline을 요약치로만 재사용하며 private scratch corpus에 의존하지 않는다.

**Acceptance:** `cargo test --locked --offline -p barochart-core --test data --test range_index`; `node scripts/rust/core-conformance.mjs --suite core-data --seed 21`. 모든 data-returning call, error, version pair, row order, column F64 bits 및 rollback state가 byte/bit exact.

## Task 3 — markets, timezone, calendar

## Checked-in fixture and comparator contract

`test/fixtures/rust-core-vectors/manifest.json` maps each JSONL row to source Node test names and the exact oracle bundle. Fixture rows carry one `scenarioId`, a sequence of `{name,args}`, expected result/error after every call, optional post-call `nativeInspect`/save/status snapshots, and raw F64 bit lists where public copying exposes them. Each scenario creates exactly one JS VM and one WASM Engine. Clean up both in `finally`; compare errors before continuing; do not retry a failed scenario in another engine.

`core-conformance.mjs` exits nonzero at the first mismatch, prints the vector id, call index, dialect/platform/tzdata metadata, and a bounded first-difference field path. It keeps the failing fixture input intact for reduction. It never treats error class equality as enough when the oracle exposes exact message/code/text, and never accepts numeric tolerance. `nativeInspect` outputs containing process-global serials are normalized only by a named manifest rule and only in those fields.
