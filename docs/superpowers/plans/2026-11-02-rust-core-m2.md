# Rust 코어 M2 구현 계획: 계약 검증기 · 데이터 저장소 · 시장/시간 · 수집 문서 · 드로잉 저장소

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** JS 코어의 데이터 계층을 Rust로 글자 그대로 옮긴다. 화면·지표·모델은 아직 없다. 모든 결과는 JS 코어와 바이트·비트 단위로 같아야 한다.

**Architecture:** `rust/crates/barochart-core`를 새로 만든다. 모듈 이름과 순서는 `scripts/native-core-bundle.mjs`의 `CORE_MODULES`를 따른다. 함수마다 JS 출처 주석을 단다.

차분 검증은 M1a 대조 하네스를 넓혀서 한다.
- Node 드라이버가 `src/core` 모듈을 직접 import해 시나리오를 실행한다.
- Rust 대조 도구가 같은 시나리오를 실행한다.
- 둘의 결과를 무손실 JSON 바이트로 비교한다.

FFI·WASM 하네스(M1b)는 이 단계에 필요 없다.

PR 세 개로 나눈다.
- **M2a** (`feat/rust-m2a-data-store`): 코어 뼈대, contracts, 체크포인트 코덱, 데이터 저장소
- **M2b** (`feat/rust-m2b-markets-ingestion`): markets(시간대 호스트 콜백), 수집 세션 문서
- **M2c** (`feat/rust-m2c-drawings`): 드로잉 저장소와 문서

**Tech Stack:** Rust 1.98.1, `barochart-js` 커널(M1a), Node 22

**Spec:** `docs/superpowers/specs/2026-11-02-rust-core-design.md`(§6, §7, §8.1 M2). 동작 명세의 정본은 다음 둘이다.

## Global Constraints

- **M1 계획의 Global Constraints를 모두 따른다.** 툴체인 래퍼, 의존성 제한, `forbid(unsafe_code)`, 금지 규칙, 문서 주석, 커밋 규칙이다.
- **오라클은 M0a가 머지된 main의 `src/core`와 `native/Resources/aster-core.js`다.** M0a 이전 동작을 따르지 않는다.
  - 키 순서 정규화(`orderedRecord`, `canonicalKeys`, `*_KEYS`)
  - 시간대 계약 v1
  - 엄격한 ISO 파서
- **글자 그대로 옮긴다**(설계 §6.4).
  - 식의 모양과 평가 순서를 지킨다.
  - 합산은 JS 순서대로 한다(dyadic RangeIndex, Neumaier 등).
  - `js_max`/`js_min`/`js_round`/`js_sign`은 커널 함수만 쓴다.
  - 숫자→문자열은 `barochart_js::num`만 쓴다. Android 방언은 `NumberDialect::PLATFORM`을 따른다.
- **엔진 전역 상태는 `Engine`(또는 그 안의 저장소 구조체)이 가진다.** static과 thread_local을 쓰지 않는다. 예: `BarStore` serial(D4)은 엔진마다 카운터를 둔다. 프로세스 전역 serial은 차분 비교에서 정규화한다.
- **오류는 `JsError { name, message, code }`로 낸다.** 문구는 이식 지도 §4의 원문을 글자 그대로 쓴다.
- **바이트 계산은 `u64`다.** 데이터 크기에 비례하는 할당은 `try_reserve`를 쓰고, 실패하면 같은 플랫폼 JS 백엔드와 같은 클래스의 오류를 낸다.
- 시드 고정 생성기만 쓴다. npm 의존성은 새로 넣지 않는다.

## Review Focus

1. **배치 이벤트의 오류 우선순위.** 옵션 → 모양 → 예산 → 순서 → 넘침 순서가 JS와 같아야 하고, 실패하면 상태가 바뀌지 않아야 한다. → Task 3 코퍼스
2. **RangeIndex 합의 비트 동등성.** 리더가 7,887건을 dyadic 질의 순서로 맞췄고, 순진한 합은 1,954건이 달랐다. 정정·prepend 뒤에도 같아야 한다. → Task 3
3. **시간대.** DST에 없는 시각과 겹치는 시각, 연도 경계(1000/9999), 고정 오프셋, 소수 ms의 TimeClip 순서(M0a Task 2 판단). → Task 4
4. **수집 문서 왕복.** `save(restore(t)) === t`가 바이트 단위로 성립해야 한다. 35개 코퍼스와 −0 시퀀스, 카운터 키 순서를 확인한다. → Task 5
5. **드로잉 이력 예산.** undo/redo 스택 길이와 이력 트리밍이 `JSON.stringify` 길이 기준과 같아야 한다. 단독 서로게이트 텍스트도 확인한다. → Task 6
